# منصة حفظ النعمة — نسخة الحسابات ولوحات التحكم

هذه النسخة تضيف وظائف حقيقية في الخادم وقاعدة البيانات، مع الحفاظ على واجهة الموقع الحالية قدر الإمكان.

## الوظائف المضافة

1. **إنشاء حساب حقيقي** بالبريد وكلمة المرور، مع اختيار فئة: فرد أو مطعم/متجر أو جمعية خيرية.
2. **تسجيل الدخول والخروج** ورمز جلسة موقّع، وتخزين كلمة المرور بصيغة PBKDF2 لا كنص مكشوف.
3. **لوحة حسب الفئة:** المطعم/المتجر يدير فائضه وحجوزاته؛ الجمعية والفرد يتابعان حجوزاتهما؛ المشرف يرى مؤشرات النظام والمستخدمين والوجبات والحجوزات.
4. **نشر فائض الطعام** من حساب مطعم/متجر أو جمعية، وحفظه في SQLite.
5. **الحجز وتحديث الكمية** داخل معاملة قاعدة بيانات لمنع الحجز المتجاوز للكمية المتاحة.
6. **إدارة المشرف:** عرض المستخدمين، إيقاف/تفعيل الحسابات، وإلغاء نشر الوجبات أو إعادة نشرها.
7. **واجهات API محمية بالصلاحيات**، مع توثيق تلقائي في `/docs`.

## ما لا يزال يحتاج إعدادًا قبل أن يعمل على موقعك

- لا يكفي رفع الواجهة إلى GitHub Pages وحده؛ يجب نشر مجلد `backend` على استضافة تدعم Python ثم وضع رابطها في `frontend/config.js`.
- تحتاج قاعدة البيانات إلى تخزين دائم في الاستضافة حتى لا تضيع البيانات عند إعادة النشر.
- حسابات المستخدمين تُنشأ بالبريد وكلمة المرور، لكن لا يوجد حتى الآن تحقق من البريد برسالة، ولا توثيق رسمي لهوية المطعم/الجمعية، ولا استعادة كلمة مرور عبر البريد، ولا إشعارات SMS/WhatsApp.
- هذه نسخة تطوير أولية للنظام؛ قبل إطلاقها للجمهور يلزم إعداد الأسرار، HTTPS، سياسة الخصوصية، نسخ احتياطي، ومراجعة أمنية.

## 1) تشغيل الخادم محليًا

من داخل مجلد `backend`:

```bash
pip install -r requirements.txt
export HIFZ_TOKEN_SECRET='ضع-هنا-سرًا-طويلًا-عشوائيًا'
uvicorn main:app --reload --host 0.0.0.0 --port 8000
```

في Windows يمكن ضبط متغير البيئة من إعدادات النظام بدل `export`.

## 2) إنشاء حساب المشرف

لا يوجد تسجيل مشرف من صفحة التسجيل العامة عمدًا. في إعدادات الاستضافة أضف المتغيرين:

- `HIFZ_ADMIN_EMAIL` = بريد المشرف
- `HIFZ_ADMIN_PASSWORD` = كلمة مرور قوية لا تقل عن 12 حرفًا

عند بدء الخادم، يُنشأ حساب مشرف بهذا البريد إذا لم يكن موجودًا. لا تضع كلمة المرور في ملفات الواجهة أو GitHub.

متغيرات أخرى:
- `HIFZ_TOKEN_SECRET`: سر طويل ثابت لتوقيع الجلسات، يجب ألا يتغير بين مرات التشغيل.
- `HIFZ_DB_PATH`: مسار ملف SQLite داخل وحدة تخزين دائمة، مثل `/var/data/hifz_alnama.db`.
- `CORS_ORIGINS`: أصل موقع GitHub Pages، مثل `https://USERNAME.github.io` (أو قائمة مفصولة بفواصل).

## 3) نشر الخادم وربطه بموقع GitHub Pages

1. ارفع مجلد `backend` إلى مستودع GitHub مستقل أو جهّز مستودعًا لنشر خدمة Python.
2. في خدمة استضافة تدعم FastAPI، اجعل أمر التثبيت `pip install -r requirements.txt` وأمر التشغيل `uvicorn main:app --host 0.0.0.0 --port $PORT`.
3. اضبط المتغيرات السابقة، واربط قرصًا دائمًا واضبط `HIFZ_DB_PATH` على مسار ذلك القرص.
4. بعد نشر الخادم، افتح `/api/health` وتأكد من أن الحالة `ok`.
5. افتح `frontend/config.js` وضع رابط الخادم المنشور دون `/` في النهاية:

```js
window.HIFZ_API_URL = 'https://YOUR-SERVICE.onrender.com';
```

6. ارفع **كل** ملفات `frontend` إلى مستودع GitHub Pages: `index.html`, `style.css`, `app.js`, `config.js`.
7. جرّب إنشاء حساب فرد، ثم أنشئ حساب مطعم/جمعية، وانشر فائضًا، ثم احجزه من حساب مختلف. جرّب حساب المشرف أيضًا.

## مسارات API الرئيسية

- `POST /api/auth/register` إنشاء حساب مستخدم.
- `POST /api/auth/login` تسجيل الدخول.
- `GET /api/auth/me` التحقق من الجلسة.
- `POST /api/auth/logout` نقطة خروج (ويُحذف الرمز من المتصفح).
- `GET /api/dashboard` بيانات لوحة الحساب حسب الفئة.
- `GET/POST /api/foods` عرض وإضافة الفائض.
- `PATCH/DELETE /api/foods/{id}` تعديل/إلغاء نشر فائض مملوك.
- `POST /api/foods/{id}/reservations` حجز كمية.
- `GET /api/reservations` حجوزات المستخدم حسب صلاحياته.
- `PATCH /api/reservations/{id}` تحديث حالة الحجز أو إلغاؤه.
- `/api/admin/users` و`/api/admin/foods/{id}` عمليات المشرف.
- `/docs` توثيق API.

## تنبيه

قاعدة SQLite محلية بالنسبة للخادم. لا تستخدم هذه النسخة لجمع بيانات حساسة أو تشغيل توزيع غذائي حقيقي قبل اختبارها ونشرها بشكل صحيح وتطبيق متطلبات سلامة الغذاء والخصوصية في الجهة المشغلة.
