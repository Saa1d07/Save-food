# منصة حفظ النعمة — نسخة مرتبطة بقاعدة بيانات

## ما الذي يعمل في هذه النسخة؟
- واجهة عربية متجاوبة مع الجوال والوضع الداكن/الفاتح.
- API باستخدام FastAPI.
- قاعدة بيانات SQLite تحفظ الفائض والحجوزات بعد إعادة تشغيل الخادم.
- إضافة فائض الطعام من الواجهة إلى قاعدة البيانات.
- تحميل الوجبات المنشورة من الخادم.
- حجز كمية من الطعام مع التحقق من الكمية المتاحة لتقليل الحجز الزائد.
- توثيق API تلقائي عبر `/docs`.

## مهم قبل الاستخدام
هذه نسخة تطوير متصلة بقاعدة بيانات، وليست نظامًا إنتاجيًا نهائيًا بعد. لا يوجد حتى الآن تسجيل دخول وصلاحيات للمستخدمين، أو لوحة إدارة، أو رسائل تحقق، أو إشعارات، أو تحقق من هوية الجهات. لا تضع بيانات شخصية أو بيانات حقيقية حساسة قبل إضافة هذه الضوابط.

## تشغيل الخادم محليًا
من مجلد `backend`:

```bash
pip install -r requirements.txt
uvicorn main:app --reload --host 0.0.0.0 --port 8000
```

ثم افتح `/docs` على عنوان الخادم لاختبار الـ API.

## ربط الواجهة بالخادم المنشور
1. انشر مجلد `backend` على خدمة تدعم Python وFastAPI (مثل Render).
2. اجعل أمر التشغيل:
   `uvicorn main:app --host 0.0.0.0 --port $PORT`
3. للحصول على حفظ دائم لقاعدة SQLite في الاستضافة، اربط قرصًا دائمًا وحدد متغير البيئة `HIFZ_DB_PATH` إلى مسار داخل القرص، مثل `/var/data/hifz_alnama.db`. من دون قرص دائم، قد تضيع البيانات عند إعادة نشر الخدمة.
4. انسخ رابط الخادم العام.
5. افتح `frontend/config.js` واستبدل القيمة الفارغة برابط الخادم، مثل:
   `window.HIFZ_API_URL = 'https://YOUR-SERVICE.onrender.com';`
6. ارفع ملفات مجلد `frontend` كاملة إلى مستودع GitHub Pages. يجب أن ترفع `index.html` و`style.css` و`app.js` و`config.js` معًا.
7. جرّب إضافة فائض ثم حدّث الصفحة وتأكد من بقائه ظاهرًا. جرّب الحجز أيضًا.

## نقاط API
- `GET /api/health` فحص الخدمة.
- `GET /api/foods` عرض الفائض المتاح.
- `POST /api/foods` إضافة فائض.
- `POST /api/foods/{food_id}/reservations` حجز كمية.
- `GET /api/reservations` عرض الحجوزات (للتطوير؛ يجب تقييده بصلاحيات قبل الإنتاج).

## الملفات
- `frontend/`: واجهة الموقع.
- `backend/main.py`: واجهة API وقاعدة البيانات.
- `backend/requirements.txt`: مكتبات Python اللازمة.
